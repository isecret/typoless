# E16-I2 SenseVoice 失败处理与 LLM 失败验证清单

> 对应 Issue: #87, #97
> 前置依赖: #81 (SenseVoice 设为默认)

## 目的

验证 SenseVoice 本地运行时架构下各类失败场景的处理行为，确保不会进入不可解释状态。

## 前置条件

1. App 已正确打包 `sherpa-onnx` 与 RNNoise 运行资源，且用户目录模型默认可用
2. 麦克风和辅助功能权限已授予

## 验证步骤

### 1. 资源缺失

| # | 操作 | 预期结果 | 通过 |
|---|------|---------|------|
| 1.1 | 删除 `lib/libsherpa-onnx-c-api.dylib` 后启动 App | ResourceValidator 报告资源异常；录音按钮不可用或提示用户 | ☐ |
| 1.2 | 删除某个 required 模型文件 | 同上，明确提示缺失项 | ☐ |
| 1.3 | 删除 `lib/libonnxruntime.1.24.4.dylib` | 同上 | ☐ |
| 1.4 | 恢复所有资源后重新启动 | App 恢复正常 | ☐ |

### 2. ASR 超时与取消

| # | 操作 | 预期结果 | 通过 |
|---|------|---------|------|
| 2.1 | 模拟本地识别响应超过 15 秒 | ASR 报超时；当前识别任务被取消；状态回到 idle/error | ☐ |
| 2.2 | 超时后立即再次录音 | 启动新的识别流程；不读取旧结果；识别正常完成 | ☐ |
| 2.3 | 录音过程中用户手动取消（transcribing 阶段） | 处理链路终止；当前本地识别被中断；不进入 LLM 或注入 | ☐ |
| 2.4 | 快速连续触发两次录音 | 前一 session 被正确取消；后一 session 正常执行 | ☐ |

### 3. Runtime 异常恢复

| # | 操作 | 预期结果 | 通过 |
|---|------|---------|------|
| 3.1 | 人工移除本地 runtime 文件后触发录音 | 本次请求报资源缺失失败 | ☐ |
| 3.2 | 恢复 runtime 文件后再次录音 | 自动恢复；识别正常完成 | ☐ |
| 3.3 | 人工破坏用户目录模型后录音 | 返回模型缺失错误 | ☐ |
| 3.4 | 重新下载模型后再次录音 | 自动恢复；识别正常完成 | ☐ |

### 4. LLM 失败处理

| # | 操作 | 预期结果 | 通过 |
|---|------|---------|------|
| 4.1 | 配置无效 LLM endpoint | ASR 结果正常获取；LLM 失败后直接报错，不注入任何文本 | ☐ |
| 4.2 | 配置 LLM 超时（极低 timeout） | 超时后直接报错，不注入任何文本 | ☐ |
| 4.3 | 注入失败（目标无文本焦点） | 菜单栏显示截断预览；点击可复制到剪贴板 | ☐ |

## 通过标准

- 所有失败场景不产生 UI 卡死或不可解释状态
- 超时和取消后可立即重新开始下一次识别
- Runtime 或模型恢复后下一次请求可正常完成
- LLM 失败不会注入 ASR 原文
- 不因资源异常留下不可恢复状态

# E16-I1 SenseVoice 端到端验证清单

> 对应 Issue: #86
> 前置依赖: #81 (SenseVoice 设为默认), #64 (录音上限与短录音静默取消), #124 (长录音分段 ASR)

## 目的

确认 SenseVoice 默认链路在真实场景中可完成一次完整输入闭环。

## 前置条件

1. App 已正确打包 `sherpa-onnx` 与 RNNoise 运行资源，且用户目录模型已下载完成
2. 麦克风和辅助功能权限已授予
3. LLM 配置有效（API Key / Endpoint）

## 验证步骤

### 1. 主链路闭环

| # | 操作 | 预期结果 | 通过 |
|---|------|---------|------|
| 1.1 | 打开浏览器地址栏或搜索框，按住快捷键说一句中文短句，松开 | 状态经 recording → processing → idle；文本注入到输入框 | ☐ |
| 1.2 | 打开备忘录 / VS Code / 其他编辑器，重复上述操作 | 文本成功注入 | ☐ |
| 1.3 | 检查菜单栏状态图标 | idle 时显示默认图标；recording 时切换；processing 时切换 | ☐ |

### 2. 懒加载行为

| # | 操作 | 预期结果 | 通过 |
|---|------|---------|------|
| 2.1 | 冷启动 App 后首次触发录音 | 本地 runtime 自动预热；首次识别可能稍慢但链路正常完成 | ☐ |
| 2.2 | 连续触发第二次录音 | 已预热 recognizer 被复用；响应速度明显快于首次 | ☐ |
| 2.3 | 完成一次识别后等待一段时间再再次录音 | 本地 runtime 仍可继续正常识别 | ☐ |

### 3. LLM 失败处理

| # | 操作 | 预期结果 | 通过 |
|---|------|---------|------|
| 3.1 | 配置一个无效 LLM endpoint，录音一句话 | ASR 识别完成后 LLM 请求失败；系统直接报错且不注入文本 | ☐ |
| 3.2 | 恢复有效 LLM endpoint 后再次录音 | 正常输出 LLM 润色结果 | ☐ |

### 4. 录音边界

| # | 操作 | 预期结果 | 通过 |
|---|------|---------|------|
| 4.1 | 按住快捷键后立即松开（< 500ms） | 静默取消，不触发 ASR/LLM 链路 | ☐ |
| 4.2 | 持续录音超过 55 秒 | AudioSegmenter 在 55s 强制切段，录音继续；分段 ASR 在后台串行执行 | ☐ |
| 4.3 | 录音中间停顿 2 秒以上（已录 ≥15s） | 静音检测触发自动切段，当前段提前进入 ASR；录音继续 | ☐ |
| 4.4 | 长录音结束后检查转写结果 | 所有分段 ASR 结果按顺序拼接；LLM 润色后注入 | ☐ |

### 5. 分段 ASR 行为

| # | 操作 | 预期结果 | 通过 |
|---|------|---------|------|
| 5.1 | 录音约 2 分钟后结束 | 产生多个分段，所有分段 ASR 成功；拼接文本完整通顺 | ☐ |
| 5.2 | 录音过程中取消 | 录音和未完成 ASR 均被取消，不注入任何文本 | ☐ |
| 5.3 | 构造拼接文本超过 8000 字符的长录音 | 返回 `transcriptTooLong` 错误，不进入 LLM | ☐ |
| 5.4 | 模拟单段 ASR 失败（如网络中断） | 整次流程失败，不注入部分文本 | ☐ |
| 5.5 | 检查 Debug 日志 | session 级分段诊断字段（segment_count, total_recording_ms 等）和 segment 级诊断字段正确输出 | ☐ |

## 备注

- 首次加载 SenseVoice 模型约需数秒，属正常行为
- 若注入失败，检查菜单栏是否显示截断文本预览，点击可复制
